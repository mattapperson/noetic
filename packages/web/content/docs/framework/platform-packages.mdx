title: Platform Packages
description: The runtime-specific adapters — local filesystem, shell, subprocess, durable storage, artifact store, webhook receiver — that keep core runtime-agnostic.
---

`@noetic-tools/core` is runtime-agnostic. It defines the adapter contracts (`FsAdapter`, `ShellAdapter`, `SubprocessAdapter`, `StorageAdapter`, `ArtifactStore`) and ships only implementations that need no platform: the in-memory ones, and `createRunnerSubprocessAdapter()`, the host's end of a remote runner over any frame link. Every backend that needs a specific runtime lives in a platform package:

| Package | Runtime | Provides |
|---|---|---|
| `@noetic-tools/platform-node` | Node.js ≥ 20 (and Bun) | Local filesystem, shell, and subprocess adapters; subprocess adapters that reach a remote runner; file-backed storage; the durable outbound queue; agent IPC; the file artifact store; the webhook receiver. |
| `@noetic/platform-browser` | Browsers, Cloudflare Workers, Vercel Edge | Core's runtime-neutral in-memory adapters, with no `node:*` imports. |

No platform package depends on another, and core depends on none, so a bundle carries only what its runtime needs. `@noetic-tools/platform-node` also depends on `@noetic-tools/acp`, for the keeper its local subprocess adapter runs ACP agents through. Importing `@noetic-tools/core` or `@noetic/platform-browser` into a browser bundle produces no `node:*` references.

## `@noetic-tools/platform-node`

```ts
import { AgentHarness } from '@noetic-tools/core';
import {
  createFileArtifactStore,
  createFileStorage,
  createLocalFsAdapter,
  createLocalShellAdapter,
  createLocalSubprocessAdapter,
} from '@noetic-tools/platform-node';

const harness = new AgentHarness({
  name: 'local-agent',
  params: {},
  environment: {
    fs: createLocalFsAdapter(),
    shell: createLocalShellAdapter(),
    subprocess: createLocalSubprocessAdapter(),
    storage: { adapter: createFileStorage() },
    artifacts: createFileArtifactStore({ dir: '.noetic/artifacts' }),
  },
});
```

| Export | What it is |
|---|---|
| `createLocalFsAdapter()` | An `FsAdapter` over `node:fs/promises`. |
| `createLocalShellAdapter()` | A `ShellAdapter` over the local shell. |
| `createLocalSubprocessAdapter(options?)` | A `SubprocessAdapter` for this machine. It runs steps in a child runtime, runs commands to completion, and — through `open` — starts a process and holds its stdio, which is how an [ACP agent](/docs/framework/acp-agents) runs. See [Local subprocess adapter](#local-subprocess-adapter). |
| `createWebSocketSubprocessAdapter({ url, token, ca? })` | A `SubprocessAdapter` whose processes run through a [remote runner](/docs/framework/acp-agents#where-the-agent-runs) (`noetic-acp serve`) dialled over WebSocket. Every upgrade carries the bearer token; `ws://` is allowed only to a loopback host. |
| `createCommandSubprocessAdapter({ command, args, env? })` | The same, for a runner started by a local command and spoken to over its stdio: `ssh host npx -y @noetic-tools/acp serve --stdio`, `docker exec -i ctr noetic-acp serve --stdio`. |
| `createFileStorage()` | A file-backed `StorageAdapter`, for [durable execution](/docs/framework/durability). |
| `createSqliteStorage({ database, table? })` | A `StorageAdapter` over one SQLite table. Pass an open `bun:sqlite`, `node:sqlite` or `better-sqlite3` database; the package imports no driver. |
| `createDurableOutboundQueue()` | The durable outbound frame queue for out-of-process runs. |
| `AgentIpcServer` / `AgentIpcClient` | Per-task IPC for live chat with a running agent. |
| `createFileArtifactStore({ dir, retention? })` | The file-backed [artifact store](#file-artifact-store). |
| `createWebhookReceiver(options?)` | An HTTP [webhook receiver](#webhook-receiver) for `mcp({ webhooks })`. |

Runtime imports are Node built-ins, `ws` (for the WebSocket runner adapter) and `@noetic-tools/acp` (for the keeper).

Both storage adapters implement `swap`, so sessions on them run under a [turn lease](/docs/framework/durability#one-writer-per-turn).

### Local subprocess adapter

`createLocalSubprocessAdapter()` is the adapter a Node harness names to run processes on its own machine, ACP agents included:

```ts
import { AgentHarness } from '@noetic-tools/core';
import { createLocalSubprocessAdapter } from '@noetic-tools/platform-node';

const harness = new AgentHarness({
  name: 'coder',
  params: {},
  environment: { subprocess: createLocalSubprocessAdapter() },
});
```

| Option | Default | Meaning |
|---|---|---|
| `storage` | none | A `StorageAdapter` for durable handle manifests, so `reattach()` and `listLive()` survive a restart. |
| `registryEntry` | none | The module a step child imports to find your steps. Without it a step runs in this process. |
| `keeper` | `true` | Run each agent `open` launches through a keeper, so it outlives this host and a later host can reattach. `false` makes it a child process that ends with the host. |
| `detachedTimeoutMs` | `0` (no limit) | How long a kept agent may run with no host attached. |
| `wrap` | none | Rewrite an agent's command just before it starts: wrap it in a sandbox, swap in a binary you ship. |
| `onStderr` | this process's stderr | Receives an agent's stderr. |
| `onLaunch` | none | Told of each agent started as this process's own child (`keeper: false`): `{ pid, exited }`. |
| `agentId` | `'local'` | Names the adapter's processes in errors. |

The remote adapters run commands and hold processes on the runner, and no step children: a runner has no Noetic runtime. They also refuse a command given `stdin`, such as a `runCode` node, because the runner's frames carry no end of input.

### File Artifact Store

`createFileArtifactStore({ dir, retention })` is the Node implementation of the `ArtifactStore` contract — where [connection](/docs/framework/connections) blobs such as screenshots, recordings, downloads, and [verification runs](/docs/framework/verification) are stored. Blobs are written once, content-addressed under `<dir>/sha256/<aa>/<hex>` with a sidecar metadata file, and each run's manifest under `<dir>/runs/<executionId>.json`.

`retention` caps each run (by default 512 MiB and 1e3 blobs, with no TTL). A blob dropped by retention shows up in a verification as a `buffer-truncated` gap rather than as missing evidence. `harness.artifacts.listRun(executionId)` lists a run's artifacts.

Without a store, a harness uses core's in-memory one (`createInMemoryArtifactStore()`). A browser host may implement the contract over IndexedDB or a remote store.

### Webhook Receiver

`createWebhookReceiver({ port, publicUrl })` is an HTTP receiver for MCP servers that deliver events by webhook. Pass it to `mcp()`:

```ts
import { mcp } from '@noetic-tools/mcp';
import { createWebhookReceiver } from '@noetic-tools/platform-node';

const receiver = createWebhookReceiver({ port: 8787, publicUrl: 'https://hooks.example.com' });

const slack = mcp({ type: 'http', url: 'https://slack-mcp.example.com/mcp', webhooks: { receiver } });
```

| Option | Default | Meaning |
|---|---|---|
| `port` | `0` (a free port) | Port to listen on. |
| `publicUrl` | the local address | The externally reachable base URL, behind a tunnel or proxy. |
| `hostname` | `127.0.0.1` | Interface to bind. Use `0.0.0.0` to accept remote senders directly. |
| `path` | `/webhooks` | Path prefix endpoints live under. |
| `maxBodyBytes` | 1 MiB | Larger bodies are refused with 413. |
| `toleranceMs` | five minutes | The accepted timestamp window. |

The contract `mcp()` consumes is transport only: `register(handler)` opens an endpoint and returns `{ url, close() }`; each POST reaches the handler as `{ headers, body }` (lowercase header names, raw body text) and is answered with the `{ status }` the handler returns. `mcp()` verifies deliveries itself with the secret it sent when subscribing.

The receiver also accepts `register({ onDelivery, secret?, signal? })` for your own webhooks, in which case it verifies each delivery — [Standard Webhooks](https://www.standardwebhooks.com) signature, five-minute timestamp window, duplicate ids — before calling `onDelivery`. Either way it refuses methods other than POST (405), oversized bodies (413), and unknown or closed endpoints (404). `signStandardWebhook()` and `verifyStandardWebhook()` are exported for senders and tests.

`@noetic/platform-browser` provides no receiver; a serverless host implements the contract over its own routing.

## `@noetic-tools/platform-cloudflare-worker`

Storage, an event endpoint, wake presets, Cron Trigger handlers and subprocess adapters for a harness on Cloudflare Workers. It imports no Cloudflare package: each helper takes the part of a binding it uses, so `env.DB`, `ctx.storage` and a Workflow's `step` fit as they are.

### Storage

```ts validate=none
import { createD1Storage, createDurableObjectStorage } from '@noetic-tools/platform-cloudflare-worker';

const shared = createD1Storage({ database: env.DB });                  // every Worker bound to the database
const perObject = createDurableObjectStorage({ sql: ctx.storage.sql }); // one Durable Object
```

Both implement `swap`, so sessions on them run under a [turn lease](/docs/framework/durability#one-writer-per-turn). Both also implement `getMany`.

#### One table for many tenants

Pass `scope` to keep each tenant's rows apart in a shared table. A scoped storage reads, lists and swaps only its own rows.

```ts validate=none
const storage = createD1Storage({ database: env.DB, scope: userId });
```

| | Table | Primary key |
|---|---|---|
| no `scope` | `(key, value)` | `key` |
| `scope` | `(scope, key, value)` | `(scope, key)` |

A table has one shape: every storage on it is scoped, or none is. A storage checks the table's columns before it reads or writes, and throws when its `scope` does not match. To drop a tenant, run `DELETE FROM noetic_storage WHERE scope = ?`.

#### Values larger than a row

The SQL adapters use a conservative 2 MB inline row budget. Pass `spill` with an R2 bucket to store values over 1 MiB by default, or values that outgrow the row budget after counting the key and scope, with a pointer in the row:

```ts validate=none
const storage = createD1Storage({
  database: env.DB,
  scope: userId,
  spill: { blobs: env.BUCKET },
});
```

| `spill` option | Type | Default | Description |
|---|---|---|---|
| `blobs` | `BlobStoreLike` | required | An R2 bucket binding, or anything with its `get`, `put` and `delete` |
| `maxBytes` | `number` | `1048576` | A value whose JSON is over this many UTF-8 bytes is spilled |
| `prefix` | `string` | `'noetic-storage'` | Leads every object key. The scope follows it |
| `movedPrefixes` | `string[]` | none | Object key prefixes of rows moved from another layout, whose pointers are followed too |

Each spilled write gets an object of its own, `<prefix>/<scope>/<key>/<uuid>`, and the write that replaces or deletes it removes the old object. `swap` still has one winner: for a spilled value it compares the object's text, then swaps on the pointer in the database. A pointer is followed only to an object under the storage's own prefix and scope, or under `movedPrefixes`, and a value shaped like a pointer cannot be stored. A failed cleanup delete is logged and leaves an orphaned object; it never fails the write. Without `spill`, a record that outgrows a row cannot be written, and under a turn lease that stops the turn with `ledger_write_failed`.

`spillStorage(storage, { blobs })` adds the same behavior to any other `StorageAdapter`.

#### Moving from your own table

Copy the rows across once, with the Workers that write to them stopped. `value` must be JSON text:

```sql
INSERT INTO noetic_storage (scope, key, value)
SELECT scope, key, value FROM old_table;
```

If the old table already points at objects in R2, rewrite those rows to this package's pointer in the same statement. The objects stay where they are, since a pointer holds the whole object key; pass their key prefix as `spill.movedPrefixes` so the storage follows them. For rows stored as a marker followed by the object key:

```sql
INSERT INTO noetic_storage (scope, key, value)
SELECT scope, key,
  CASE WHEN substr(value, 1, length(:marker)) = :marker
    THEN json_object('noetic:spilled', substr(value, length(:marker) + 1))
    ELSE value
  END
FROM old_table;
```

To keep the old table, pass its name as `table`. It needs the columns above under those names, and any other column must be nullable or have a default.

### Events from outside

`eventEndpoint` turns a request you accept into an event a source emits, and answers the provider only once the event is stored:

```ts validate=none
import { eventEndpoint, standardWebhookVerifier } from '@noetic-tools/platform-cloudflare-worker';

const receive = eventEndpoint({
  harness, // started before the event is emitted
  emit: (event) => mail.emit(event),
  verify: standardWebhookVerifier({ secret: env.WEBHOOK_SECRET }),
  toEvent: (body, request) => ({
    type: 'received',
    id: request.headers.get('webhook-id') ?? crypto.randomUUID(),
    payload: JSON.parse(body),
  }),
});

export default { fetch: (request: Request) => receive(request) };
```

It answers `200` when the event is stored, `503` when it could not be (so the provider sends it again), `401` when `verify` refuses or throws, `400` when `toEvent` throws, `204` when `toEvent` returns `undefined`, and `405` for anything but a POST. A delivery that arrives twice with the same event id starts one turn.

Pass `harness` so the endpoint starts it before it emits. Until the harness has started, no trigger is listening, and a source keeps an emitted event in memory only. On a Worker that memory is gone after the request, so without `harness` the first request of a cold Worker could answer `200` for an event nothing stored. `standardWebhookVerifier` throws when it is built if the secret is not base64.

### Waking parked turns

A Worker has no process between requests, so build the harness with `park: { autoWake: false }` and pick one of two presets to call [`harness.wake()`](/docs/framework/durability#parked-turns).

**A Durable Object alarm:**

```ts validate=none
import { alarmWake, createDurableObjectStorage } from '@noetic-tools/platform-cloudflare-worker';

export class Agent extends DurableObject {
  #harness = buildHarness(createDurableObjectStorage({ sql: this.ctx.storage.sql }));
  #wake = alarmWake({ harness: this.#harness, alarms: this.ctx.storage });

  async alarm() {
    await this.#wake.alarm(); // runs what is due, waits for it, sets the next alarm
  }

  async message(text: string, messageId: string) {
    await this.#harness.execute(text, { threadId: 'main', messageId });
    return this.#harness.getAgentResponse({ threadId: 'main' });
  }
}
```

You never set the alarm yourself. `alarmWake` listens to [`harness.onWakeTimeChange()`](/docs/framework/durability#parked-turns) and keeps the object's alarm at the harness's next wake time. A turn that parks does not answer until its alarm is set.

A turn [cut](/docs/framework/durability#one-writer-per-turn) by a lost lease or a failed write is brought back by the same alarm after its back-off, so the object does not catch those errors itself.

Name the lease holder after the object, so the object that comes back after its isolate died takes its turns over at once: `environment.storage.lease.holder = durableObjectHolder(this.ctx)` (the object's id). One holder name must drive a thread from one place at a time. `durableObjectEnvironment(this.ctx)` returns the whole `environment` for a harness the object owns: this storage, this holder, and `park: { autoWake: false }`.

**Sharing the alarm.** A Durable Object has one alarm, and yours may need it too. Pass `schedule` in place of `alarms`, and merge with `sharedAlarm`:

```ts validate=none
import { alarmWake, sharedAlarm } from '@noetic-tools/platform-cloudflare-worker';

export class Session extends DurableObject {
  #alarms = sharedAlarm(this.ctx.storage);
  #wake = alarmWake({ harness: this.#harness, schedule: this.#alarms.schedule('noetic') });
  #retries = this.#alarms.schedule('retries');

  async alarm() {
    await this.#alarms.alarm(async () => {
      await this.#wake.alarm();                      // says noetic's next time again
      await this.#retries(await this.retryWrites()); // yours, or undefined for none
    });
  }
}
```

Outside `alarm()`, a part's time only brings the alarm forward: after the isolate restarts, the other parts' times are not in memory, and an alarm that fires early is harmless. Inside it, the times that came are forgotten, each part says its next one, and the alarm is set to the earliest, or deleted when no part wants one. `wantedAt()` on either returns the time asked for.

A [`cron()`](/docs/framework/connections) trigger runs on this preset unchanged. The alarm is set to the next tick as well as to parked deadlines, and `alarm()` delivers the ticks that fell due while nothing ran. The first tick's alarm is set when the harness starts, so an object that only runs on a schedule needs one call to `harness.start()` when it is created.

**A Cloudflare Workflow, one instance per turn:**

```ts validate=none
import { runTurn, startTurn, wakeTurn, type TurnParams } from '@noetic-tools/platform-cloudflare-worker';

export class Turns extends WorkflowEntrypoint<Env, TurnParams> {
  async run(event: WorkflowEvent<TurnParams>, step: WorkflowStep) {
    return runTurn({ harness: buildHarness(this.env), step, turn: event.payload });
  }
}

// A message arrives: one instance per message, however often it is delivered.
const instanceId = await startTurn(env.TURNS, { threadId, messageId, input: text });

// The event a parked turn waits for arrived, or a person answered a held call.
await wakeTurn(env.TURNS, instanceId);
```

The instance runs the turn until it parks, sleeps until the turn's deadline or a wake, and runs it again. A cut turn sleeps until its back-off is over the same way. This preset has no object that is always there, so for a `cron()` trigger add a Cloudflare Cron Trigger whose `scheduled` handler calls `harness.start()` and awaits `harness.waitForIdle()`. Everything the turn did is in the harness's storage, so a Workflow step that is retried repeats nothing.

### Cron Triggers

A Cloudflare Cron Trigger reaches an object that has never run, which an alarm cannot. Route the Worker's `fetch` and `scheduled` handlers to one named Durable Object, and let the object own one harness: requests, alarms and ticks all go through the same `harness.execute()`.

```ts validate=none
import {
  alarmWake,
  type CronTick,
  cronTurn,
  durableObjectEnvironment,
} from '@noetic-tools/platform-cloudflare-worker';

export class Agent extends DurableObject<Env> {
  #harness = new AgentHarness({
    name: 'agent',
    agentGraph,
    environment: durableObjectEnvironment(this.ctx), // SQLite storage, the object's id as lease holder
  });
  #wake = alarmWake({ harness: this.#harness, alarms: this.ctx.storage });
  #digest = cronTurn({
    cron: '0 8 * * *',
    name: 'digest',
    harness: this.#harness,
    wake: this.#wake,
    input: 'Write the morning digest.',
  });

  async alarm() {
    await this.#wake.alarm();
  }

  async tick(tick: CronTick) {
    await this.#digest(tick);
  }

  async message(text: string, messageId: string) {
    await this.#harness.execute(text, { threadId: 'main', messageId });
    return (await this.#harness.getAgentResponse({ threadId: 'main' })).text;
  }
}

export default {
  async fetch(request, env) {
    const { text, messageId } = await request.json();
    return Response.json(await env.AGENT.getByName('main').message(text, messageId));
  },
  async scheduled(controller, env) {
    await env.AGENT.getByName('main').tick({
      cron: controller.cron,
      scheduledTime: controller.scheduledTime,
    });
  },
} satisfies ExportedHandler<Env>;
```

Each tick uses `cron:<name>:<scheduledTime>` as both its thread and message ID. HTTP requests and scheduled turns share the harness. Each tick gets its own checkpoint. Pass a function as `input` to build the message from the tick.

- **Duplicate ticks.** The preset queues delivery. A duplicate joins the active turn or replays its stored answer. Replay works for as long as you keep the tick's thread.
- **Eviction and backoff.** The alarm, or a later tick, resumes due work from the object's SQLite. A new tick can run while an older thread waits to retry.
- **Failed turns.** The handler rejects with the tick's failure. If the host retries, send the same tick to reuse its record. Parked and cut turns stay on the harness's alarm path.

A tick whose `cron` is not the handler's is ignored, so one `tick` method can pass every tick to several `cronTurn` handlers.

**A scan.** For work that keeps its own cursor and is not a harness turn, `cronWake` runs one scan per tick over any storage with `swap`:

```ts validate=none
import { createD1Storage, cronWake } from '@noetic-tools/platform-cloudflare-worker';

const scan = cronWake<Env>({
  cron: '* * * * *',
  name: 'outbox',
  storage: (env) => createD1Storage({ database: env.DB }),
  run: (env, through) => sendDue(env, through),
});

export default {
  scheduled: (controller, env) => scan(controller, env),
} satisfies ExportedHandler<Env>;
```

A scan that succeeds covers every earlier tick. A duplicate tick, or one that arrives while another Worker scans, starts nothing. A scan that throws is tried again by the next tick, and a Worker that died gives up its lease after 16 minutes. `run` may see the same work twice, so give its effects stable keys.

### Processes on another machine

A Worker cannot start a process. Its subprocess adapters run processes through a [remote runner](/docs/framework/acp-agents#where-the-agent-runs) (`noetic-acp serve`) over a WebSocket, so an [ACP agent](/docs/framework/acp-agents) can run for a harness on Workers.

```ts validate=none
import {
  createFetchSubprocessAdapter,
  createSocketSubprocessAdapter,
} from '@noetic-tools/platform-cloudflare-worker';

// The Worker dials the runner: a fetch upgrade that carries the bearer token.
const dialled = createFetchSubprocessAdapter({ url: 'wss://build-host:7000', token: env.RUNNER_TOKEN });

// The runner's host dialled in, and this Durable Object accepted its socket.
const dialledIn = createSocketSubprocessAdapter(() => this.takeRunnerSocket());
```

| Export | What it is |
|---|---|
| `createFetchSubprocessAdapter({ url, token, fetch? })` | Each link is one WebSocket, opened by a `fetch` upgrade to the runner's `wss://` URL. `ws://` is allowed only to a loopback host. |
| `createSocketSubprocessAdapter(accepted)` | Each link takes one socket from `accepted()`: a socket the Durable Object accepted (`socket.accept()`), which no other link uses. Closing the link closes the socket. |

Both hold processes on the runner and run commands that take no `stdin`; neither runs step children. A socket accepted for hibernation (`state.acceptWebSocket`) delivers its messages to the object's handlers and not to listeners, so build a `FrameLink` from those and pass it to `createRunnerSubprocessAdapter()` from `@noetic-tools/core`.
