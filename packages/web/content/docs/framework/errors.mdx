## Quick Example

```ts
import { AgentHarness, isNoeticError } from '@noetic-tools/core';

declare const harness: AgentHarness;

try {
  const result = await harness.execute('Do something');
} catch (e) {
  if (isNoeticError(e)) {
    console.log(e.noeticError.kind); // e.g. 'step_failed'
    console.log(e.message);         // Human-readable description
  }
}
```

Noetic wraps every framework-level failure in a structured `NoeticError` discriminated union. Instead of catching generic exceptions and guessing what went wrong, you can match on the `kind` field and access typed metadata for each error variant.

## NoeticError Type

`NoeticError` is a discriminated union with a `kind` field. Each variant carries context-specific data:

| `kind` | Key Fields | When it occurs |
|---|---|---|
| `step_failed` | `stepId`, `cause: Error`, `retriesExhausted` | A step throws after exhausting retries. |
| `model_refused` | `stepId`, `refusal: string` | The model returns a refusal instead of content. |
| `model_parse_error` | `stepId`, `raw: string`, `schema: StandardSchemaV1`, `zodError: ZodError` | Structured output fails schema validation. `schema` is the Standard Schema v1 validator; `zodError` stays populated for backward compatibility — the real `ZodError` for Zod schemas, a synthetic `custom`-issue `ZodError` adapted from the vendor's Standard Schema issues otherwise. |
| `model_rate_limit` | `stepId`, `retryAfter?: number` | The LLM provider returns a rate-limit response. |
| `fork_partial` | `stepId`, `succeeded[]`, `failed[]` | Thrown by `inParallel` mode `'all'` when any path fails, and by `'race'` when every path fails. (Mode `'settle'` never throws this — it reports failures in its `SettleResult` array instead.) |
| `spawn_summary_failed` | `stepId`, `childOutput: unknown`, `summaryCause: Error` | A spawn's child succeeded but a context layer's `onReturn` hook (such as a summarizer) failed. Never thrown: the spawn returns the child's unsummarized output, and this error is reported as a layer diagnostic and a `spawn.summary_failed` span event. |
| `channel_timeout` | `channelName`, `timeout: number` | A `recv()` call — or a back-pressured `send()` parked on a full queue — exceeded its timeout. |
| `channel_closed` | `channelName` | Attempted to send on a closed external channel. |
| `cancelled` | `reason?: string` | The execution was cancelled via `ctx.abort()` or `harness.cancel()` — including a parent's cancellation cascading into an `inParallel` path or `spawn` child. Pending channel `recv` calls (and parked back-pressure `send` calls) on the aborted context reject with this kind immediately, and an in-flight model call or ACP agent turn is cut short. Under a [graceful stop](/docs/framework/runtime#graceful-stop) (`cancel(ctx, { drainMs })`), the steps, rounds and tool calls it held back throw this kind once the drain ends. |
| `budget_exceeded` | `field: 'cost' \| 'steps' \| 'duration'`, `limit`, `actual` | A budget guard detected the run exceeded its limits. |
| `steering_denied` | `guidance?: string` | A context layer's steering hook (`beforeToolCall` / `afterModelCall`) returned a deny decision and the runtime blocked the action, or the harness `approveToolCall` approver refused an `invokeTool` call to a tool with `needsApproval`. `guidance` carries the corrective feedback, if any. |
| `item_schema_mismatch` | `category: 'items' \| 'developerMessages' \| 'toolCalls' \| 'toolResults'`, `itemType?: string` | An item failed extension-schema validation in the `ItemSchemaRegistry`: a category item (e.g. a tool result) matched none of the schemas registered for its category, or an unknown item type matched no registered schema under strict mode. `itemType` is set for the unknown-type case. |
| `connection_unavailable` | `connection`, `reason` | A connection is disconnected, its pool stayed full past `waitMs`, or an event stream a step was waiting on ended. |
| `connection_failed` | `connection`, `op`, `error` | The server refused or failed the operation. `error.code` is one of the codes connection profiles define, such as `malformed`, `guarded` or `ambiguous`. |
| `connection_ref_invalid` | `connection`, `reason` | A ref was not issued by this harness, belongs to a different connection than the call's target, was used from another thread, or is stale. |
| `connection_secret_refused` | `connection`, `op` | A `secret()` was used outside a field the operation marks `sensitive`, or by the model. |
| `connection_input_required` | `connection`, `request` | A long-running operation asked a question nobody could answer. |
| `connection_resume_refused` | `connection`, `reason` | A resumed run's connection was replaced and cannot safely be driven again. |
| `decision_refused` | `threadId`, `action`, `reason` | A decision passed to `harness.execute()` does not fit what the thread is waiting on: no turn is stuck, it carries both an `action` and an `output`, or its action is the wrong kind for the decision. |
| `hold_refused` | `callId`, `reason` | `harness.execute()` could not take a decision for a [held tool call](/docs/framework/steps/invoke-tool#human-in-the-loop-approval). |
| `lease_lost` | `executionId`, `term`, `reason` | Another harness holds or took this thread's turn. See [one writer per turn](/docs/framework/durability#one-writer-per-turn). A turn this stops mid-run is cut, not failed: its response resolves with `cut`. |
| `turn_stuck` | `executionId`, `path`, `from`, `to` | A turn resumed under a newer flow version would have to redo a step that already had a lasting effect, so it stopped. A turn that began on a JSON workflow resumes on that workflow and does not reach this unless it could not be rebuilt. See [flow versions](/docs/framework/durability#flow-versions). |
| `ledger_write_failed` | `executionId`, `path`, `cause` | Under a turn lease, a durable record could not be written, so the turn stopped. It is cut and runs again after a back-off; only once it has been cut `lease.cut.attempts` times does it fail with this error. Also thrown by `harness.forget()` when a spend record (`path` `spend:<id>`) could not be settled; nothing was deleted. |
| `verify_act_failed` | `stepId`, `cause: Error`, `run?: BlobRef` | A `step.verify`'s `act` threw. The verification run is recorded first, with the failure as evidence, and `run` points at it. |

### Full Type Definition

```ts validate=none
type NoeticError =
  | { kind: 'step_failed'; stepId: string; cause: Error; retriesExhausted: boolean }
  | { kind: 'model_refused'; stepId: string; refusal: string }
  | { kind: 'model_parse_error'; stepId: string; raw: string; schema: StandardSchemaV1; zodError: ZodError }
  | { kind: 'model_rate_limit'; stepId: string; retryAfter?: number }
  | { kind: 'fork_partial'; stepId: string; succeeded: Array<{ stepId: string; value: unknown }>; failed: Array<{ stepId: string; error: NoeticError }> }
  | { kind: 'spawn_summary_failed'; stepId: string; childOutput: unknown; summaryCause: Error }
  | { kind: 'channel_timeout'; channelName: string; timeout: number }
  | { kind: 'channel_closed'; channelName: string }
  | { kind: 'cancelled'; reason?: string }
  | { kind: 'budget_exceeded'; field: 'cost' | 'steps' | 'duration'; limit: number; actual: number }
  | { kind: 'steering_denied'; guidance?: string }
  | { kind: 'item_schema_mismatch'; category: 'items' | 'developerMessages' | 'toolCalls' | 'toolResults'; itemType?: string }
  | { kind: 'connection_unavailable'; connection: string; reason: string }
  | { kind: 'connection_failed'; connection: string; op: string; error: { code: ConnectionErrorCode; message: string; details?: Record<string, unknown> } }
  | { kind: 'connection_ref_invalid'; connection: string; reason: string }
  | { kind: 'connection_secret_refused'; connection: string; op: string }
  | { kind: 'connection_input_required'; connection: string; request: { id: string; message: string; schema?: JsonSchema } }
  | { kind: 'connection_resume_refused'; connection: string; reason: string }
  | { kind: 'decision_refused'; threadId: string; action: string; reason: string }
  | { kind: 'hold_refused'; callId: string; reason: string }
  | { kind: 'lease_lost'; executionId: string; term: number; reason: string }
  | { kind: 'turn_stuck'; executionId: string; path: string; from: string; to: string }
  | { kind: 'ledger_write_failed'; executionId: string; path: string; cause: Error }
  | { kind: 'verify_act_failed'; stepId: string; cause: Error; run?: BlobRef };
```

### Model provider failures

A failing provider call in a `callModel` or `decide` step never reaches you as a raw `Error`. A 429 becomes `model_rate_limit`, a failure caused by cancellation becomes `cancelled`, and anything else becomes `step_failed` with the provider's error on `cause`.

## NoeticErrorImpl Class

`NoeticErrorImpl` extends the standard `Error` class, so it works with `try/catch` and stack traces. The structured error data lives on the `.noeticError` property:

```ts validate=none
class NoeticErrorImpl extends Error {
  readonly noeticError: NoeticError;
  constructor(error: NoeticError);
}
```

The `message` string is auto-generated from the error kind and its fields. For example, a `step_failed` error produces:

```
Step 'fetch-data' failed: Connection refused
```

## isNoeticError Type Guard

Use `isNoeticError()` to narrow an `unknown` catch value:

```ts validate=none
import { isNoeticError } from '@noetic-tools/core';

function isNoeticError(e: unknown): e is NoeticErrorImpl;
```

This is an `instanceof` check against `NoeticErrorImpl` with a structural fallback: any `Error` carrying a `noeticError` object whose `kind` is a string also passes. The fallback keeps the guard reliable when more than one copy of the framework is loaded (mixed `src`/`dist` resolution, duplicated `node_modules`), where a plain `instanceof` would fail across module copies. The inner `kind` is not validated against the closed union, so errors minted by a newer framework version still pass.

## The Original Error

A `NoeticError` never drops the error it wraps. When a code step throws, the caller gets a `step_failed` error whose standard `cause` is the thrown error, so its class, name and own fields survive. An error that crosses several code steps is wrapped once per step; `failureCause()` walks the chain and returns the error the failure started from:

```ts validate=none
import { failureCause, isNoeticError } from '@noetic-tools/core';

try {
  await harness.run(pipeline, input);
} catch (e) {
  const original = failureCause(e);
  if (original instanceof BillingError) {
    // branch on your own typed failure
  }
  if (isNoeticError(e) && e.noeticError.kind === 'step_failed') {
    console.log(e.noeticError.stepId, e.cause);
  }
}
```

A thrown value that is not an `Error` is wrapped in an `Error` whose own `cause` is that value; `failureCause()` returns that wrapper, so read its `cause` for the thrown value. `failureCause()` returns a `NoeticError` that carries no cause (`cancelled`, `budget_exceeded`, ...) and any other value as is.

## Handling Errors in Loops

Loops accept an `onError` callback that receives the structured error and returns a recovery action:

```ts
import { callModel, loop, until } from '@noetic-tools/core';

const resilientLoop = loop({
  id: 'retry-loop',
  steps: [callModel({ id: 'generate', model: 'openai/gpt-4o' })],
  until: until.noToolCalls(),
  onError(error, ctx) {
    if (error.kind === 'model_rate_limit') {
      return 'retry';  // Try the same iteration again
    }
    if (error.kind === 'step_failed' && !error.retriesExhausted) {
      return 'skip';   // Move to the next iteration
    }
    return 'abort';    // Re-throw the error
  },
});
```

| Return value | Behavior |
|---|---|
| `'retry'` | Re-execute the same iteration immediately. |
| `'skip'` | Skip this iteration and continue with the previous output. |
| `'abort'` | Re-throw the error, ending the loop. |

## Matching on Error Kind

Because `NoeticError` is a discriminated union, TypeScript narrows the type after checking `kind`:

```ts
declare const e: unknown;

if (isNoeticError(e)) {
  const err = e.noeticError;

  switch (err.kind) {
    case 'model_parse_error':
      // TypeScript knows: err.raw, err.schema, err.zodError
      console.log('Validation errors:', err.zodError.issues);
      break;

    case 'fork_partial':
      // TypeScript knows: err.succeeded, err.failed
      console.log(`${err.succeeded.length} paths ok, ${err.failed.length} failed`);
      break;

    case 'budget_exceeded':
      // TypeScript knows: err.field, err.limit, err.actual
      console.log(`${err.field} limit: ${err.limit}, used: ${err.actual}`);
      break;
  }
}
```

## NoeticConfigError

`NoeticConfigError` is a separate class from `NoeticError`. It reports a setup mistake — an invalid builder option, missing credentials, a workflow that references something unregistered — rather than a failure while running. Builders throw it when you construct a step; `AgentHarness.run()` and `execute()` check what they can before the first step runs.

```ts validate=none
class NoeticConfigError extends Error {
  readonly code: string;    // SCREAMING_SNAKE_CASE, e.g. 'MISSING_API_KEY'
  readonly hint: string;    // a sentence saying what to do next
  readonly docsUrl: string; // this page, at the section for `code`
}

function isNoeticConfigError(e: unknown): e is NoeticConfigError;
```

`docsUrl` defaults to `https://noetic.tools/docs/framework/errors#<code in lower case>` — the matching section below. For example, `MISSING_API_KEY` links to `#missing_api_key`.

```ts
import { isNoeticConfigError, loop, until } from '@noetic-tools/core';

try {
  loop({ id: '', steps: [], until: until.maxSteps(10) });
} catch (e) {
  if (isNoeticConfigError(e)) {
    console.error(`${e.code}: ${e.message}\n${e.hint}\nSee ${e.docsUrl}`);
  }
}
```

## Configuration Error Codes

Every `code` a `NoeticConfigError` can carry, with its cause and fix.

### Credentials and Harness Setup

#### NO_LLM_PROVIDER

**Cause:** A `callModel` or `decide` step needs a model, but the harness has no LLM credentials. `AgentHarness.run()` and `execute()` raise this before any step runs when the model step is visible in the step tree; a model step chosen at run time raises it when it is reached.

**Fix:** Pass `callModelDefaults: { apiKey: '...' }` to `AgentHarness` (it defaults to the Noetic platform) or set `NOETIC_API_KEY`. For OpenRouter directly, pass `callModelDefaults: { provider: 'openrouter', apiKey: '...' }` or set `OPENROUTER_API_KEY`.

#### MISSING_API_KEY

**Cause:** `createOpenRouterEmbed()` was called without an OpenRouter API key.

**Fix:** Pass the key explicitly, for example `createOpenRouterEmbed(process.env.OPENROUTER_API_KEY)`.

#### MISSING_CALL_MODEL

**Cause:** A `steering()` rule is evaluated by an LLM, but no model call is available to the layer.

**Fix:** Give the harness LLM credentials (see [`NO_LLM_PROVIDER`](#no_llm_provider)), or use a rule that does not need a model.

#### NO_STEP_CONFIGURED

**Cause:** `harness.execute()` (or the session API) was called on a harness built without an `agentGraph`.

**Fix:** Pass `agentGraph` to the `AgentHarness` constructor, or drive steps directly with `harness.run(step, input, ctx)`.

#### FORGET_CHILD_UNREACHABLE

**Cause:** `harness.forget()` found a child the run had a subprocess adapter run out of process that has not finished, and no adapter this harness knows of can be the one that ran it — typically a `detachedSpawn` given its own `subprocess` by another harness. Nothing was settled or deleted.

**Fix:** Pass that adapter: `harness.forget(scope, { subprocesses: [adapter] })`. The forget stops the child if it still runs, then deletes what it kept.

#### INVALID_FORGET_SCOPE

**Cause:** `harness.forget()` was given a scope with neither a `threadId` nor an `executionId`, or an empty `threadId`.

**Fix:** Pass `{ threadId }` to forget a thread, or `{ executionId }` to forget one execution. Forget never falls back to the default thread.

#### INVALID_LEASE_OPTIONS

**Cause:** `environment.storage.lease` has a `ttlMs` that is not a finite number above 0, a `waitMs` that is negative or not finite, or an empty `holder`.

**Fix:** Correct the value, or leave it out for the default (`ttlMs` 30 seconds; `waitMs` one `ttlMs` and a little more).

#### MISSING_HARNESS_CONTEXT

**Cause:** A `workflow()` or `dynamicWorkflow()` step ran on a context with no harness attached.

**Fix:** Run the step through `AgentHarness.run()` (or `execute()`), which attaches the harness to the context.

#### STEP_LEDGER_RETENTION_INVALID

**Cause:** `environment.storage.stepLedgerRetention` has a cap that is not a positive number or `Infinity`.

**Fix:** Omit the field to take the default, pass a positive number, or pass `Infinity` to remove the cap.

#### ADAPTER_INVALID

**Cause:** `environment.fs`, `environment.shell` or `environment.subprocess` is neither an adapter of that kind nor a set of named ones, or an entry of a named set holds no adapter under `adapter`. A value is an adapter when it has its kind's method (`readFile`, `exec`, `spawn`), so a partial test double without it fails this way. So does a plain object that is both — it has that method and an `{ adapter }` entry — and a named set whose entry called `default` is not its default: that name is the default adapter's.

**Fix:** Pass one adapter, or `{ <name>: { adapter, displayName?, description?, default? } }`. Give a test double its kind's method. Rename an entry called `default`, or mark it `default: true`. See [Named adapters](/docs/framework/runtime#named-adapters).

#### ADAPTER_SET_EMPTY

**Cause:** A named adapter set in `environment` has no entries.

**Fix:** Give it at least one `{ adapter }` entry, or leave the field out for the in-memory adapter.

#### ADAPTER_DEFAULT_MISSING

**Cause:** A named adapter set has several entries and none is marked `default: true`, or its one entry is marked `default: false`.

**Fix:** Add `default: true` to the adapter that anything naming none should use. On a set of one, drop `default: false`: its entry is always the default.

#### ADAPTER_DEFAULT_AMBIGUOUS

**Cause:** A named adapter set marks more than one entry `default: true`.

**Fix:** Leave `default: true` on one entry only.

#### ADAPTER_UNKNOWN

**Cause:** Something asked for an adapter by a name the harness lacks: `ctx.adapters.fs.get(name)`, an ACP step's or `acp-agent` node's `subprocess`, `fs` or `shell`, or a preset's `subprocess` name. The message lists the names the harness has.

**Fix:** Use one of those names, or add the name to that kind in `environment`.

#### ADAPTER_NOT_IN_CHILD

**Cause:** A step named a harness adapter (`step.acpAgent({ subprocess: 'builder' })`, `ctx.adapters.fs.get('builder')`) while running out of process, in a child the local subprocess adapter started (`createLocalSubprocessAdapter({ registryEntry })`). Named adapters do not reach an out-of-process child: it has only its own in-memory `fs`, `shell` and `subprocess`.

**Fix:** Run the step in-process, or name no adapter in it. See [Out-of-process children](/docs/framework/operators/spawn#out-of-process-children).

#### CHECKPOINT_SCHEMA_MISMATCH

**Cause:** `harness.restore()` found a checkpoint written by a runtime version whose snapshot schema this version does not recognize.

**Fix:** Clear the snapshot with `CheckpointStore.clear()` and restart the execution.

#### SUBPROCESS_CANNOT_OPEN

**Cause:** Something needed to start a process and hold its stdio — an ACP agent, or a stdio MCP server started with `spawnOn()` or `agent.spawn` — and the subprocess adapter it landed on has no `open`. An agent lands on the adapter its step names, else the one its preset names, else the harness's default; nothing stands in for it. The default adapter of a harness given no `environment.subprocess` runs steps in memory and has no `open`, so `claudeCode()` on such a harness fails this way. So does an agent connected by hand with no harness adapters at all.

**Fix:** Give the harness an adapter that has `open` — `environment: { subprocess: createLocalSubprocessAdapter() }` from `@noetic-tools/platform-node` runs processes on this machine — or name another one that does (`subprocess: 'builder'` on the step or the preset).

#### SUBPROCESS_NAME_WITHOUT_HARNESS

**Cause:** An agent that names a harness subprocess adapter (`claudeCode({ subprocess: 'builder' })`) was connected with no harness adapters to find the name among, usually by calling `agent.connect()` by hand.

**Fix:** Run the agent as a step, so the harness passes its `environment.subprocess`.

#### SUBPROCESS_RUNS_NO_STEPS

**Cause:** A step was dispatched (`spawn`, `detachedSpawn`) to a subprocess adapter that only starts commands and holds their stdio: one built with `createLinkSubprocessAdapter()`, or one that reaches a remote runner (`createRunnerSubprocessAdapter()`, `createWebSocketSubprocessAdapter()`, `createCommandSubprocessAdapter()`, `createSocketSubprocessAdapter()`, `createFetchSubprocessAdapter()`). Running a step needs the Noetic runtime and your program's code where it runs, and a runner has neither.

**Fix:** Run steps through an adapter that has both — `createLocalSubprocessAdapter()`, or the in-memory default — and name the other one where a command or an agent should run: `environment: { subprocess: { here: { adapter: createLocalSubprocessAdapter(), default: true }, builder: { adapter: runner } } }`, then `subprocess: 'builder'` on the step.

#### SUBPROCESS_CANNOT_END_INPUT

**Cause:** A command was given `stdin` and sent to a subprocess adapter that reaches a remote runner — most often a JSON workflow `runCode` node, which passes its input on stdin. The runner's frames carry no end of input, so the command would wait for one and never finish.

**Fix:** Run it through an adapter on this machine (`createLocalSubprocessAdapter()`), or give the command its input as an argument or a file.

### Step Builders

#### EMPTY_STEP_ID

**Cause:** A step builder (`runCode`, `callModel`, `invokeTool`, `loop`, `spawn`, `withContext`, `inParallel`, `conditional`, `schedule`, `decide`, `routeSwitch`, `workflow`, `step.acpAgent`) or `registerStep()` got an empty `id`.

**Fix:** Give every step a unique, non-empty `id`, for example `runCode({ id: 'fetch-data', ... })`.

#### EMPTY_STEP_ARRAY

**Cause:** An empty array was given where a step goes (`harness.run`, `harness.detachedSpawn`, `agentGraph`, a `spawn` or `withContext` child, a `schedule` body, an `inParallel` path, a `conditional` route's pick, or a `when`/`otherwise` clause). An array of steps runs in sequence and needs at least one step.

**Fix:** Pass the steps to run, or a single step.

#### INVALID_STEP_IN_ARRAY

**Cause:** An element of an array of steps is not a step: a nested array, `null` or another non-object, or an object without a known step `kind` and a string `id`. The array is checked where it becomes a step (the builder, `when`/`otherwise`, `harness.run`, `detachedSpawn`, the harness constructor for `agentGraph`, or when an `inParallel` path or a `conditional` route's pick is resolved), so it fails there instead of as a `TypeError` mid-run. Nested arrays are rejected, not flattened. TypeScript rejects these arrays at compile time; the check covers untyped callers.

**Fix:** Put only steps in the array. Spread a nested array into its parent (`[a, ...rest]`) rather than nesting it.

#### MISSING_EXECUTE_FUNCTION

**Cause:** `runCode()` or `tool()` was called without an `execute` function.

**Fix:** Pass an async `execute` function — `execute: async (input, ctx) => result` for `runCode`, `execute: async (args, toolCtx) => result` for `tool`.

#### EMPTY_TOOL_NAME

**Cause:** `tool()` got an empty `name`.

**Fix:** Pass a unique name, for example `tool({ name: 'greet', ... })`.

#### MISSING_TOOL

**Cause:** `invokeTool()` was called without a `tool`.

**Fix:** Pass a tool built with `tool()`.

#### MISSING_MODEL

**Cause:** `callModel()` got an empty `model`, a `callModel` step has neither its own `model` nor a harness `model`, or a `decide()` step has neither its own `model` nor a harness `decisionModel`.

**Fix:** Pass a non-empty model id such as `'anthropic/claude-sonnet-4-20250514'`, on the step or as `model` on the harness. For `decide`, set `model` on the step or `decisionModel` on the harness.

#### UNKNOWN_TOOL_CHOICE

**Cause:** A `callModel` step's `toolChoice: { tool }` names a tool the step cannot call. `callModel()` (and the JSON hydrator) throws it at build time when `tools` is an eager array without that client tool; the harness throws it at request time, before anything is sent, when the tool is outside the unified tool set or the step's restriction.

**Fix:** Force a client tool the step offers — add it to `tools`, or register it through a context layer — or use `toolChoice: 'required'` to make the model call any allowed tool. Server tools cannot be forced.

#### MISSING_JSON_SCHEMA

**Cause:** A tool input schema or a structured-output schema cannot be turned into JSON Schema for the model.

**Fix:** Use a schema that implements `StandardJSONSchemaV1` (Zod does), or pass `inputJsonSchema` on `tool()` / `outputJsonSchema` on the model step.

#### MISSING_LOOP_BODY

**Cause:** `loop()` got an empty `steps` array.

**Fix:** Add at least one step to `steps`.

#### MISSING_UNTIL_PREDICATE

**Cause:** `loop()` was called without an `until` predicate.

**Fix:** Pass one, for example `until: until.maxSteps(10)`. Use `until.never()` for a loop that only an error or cancellation ends.

#### MISSING_CHILD_STEP

**Cause:** `spawn()` or `withContext()` was called without a `child` step.

**Fix:** Pass the step to run inside the child context as `child`.

#### MISSING_CONTEXT_LAYERS

**Cause:** `withContext()` was called without `context` layers.

**Fix:** Pass the layers to provide, for example `context: [scratchpad()]`.

#### MISSING_MERGE_FUNCTION

**Cause:** `inParallel()` in `'all'` or `'settle'` mode was called without `merge`.

**Fix:** Pass a `merge` function that combines the path results into one output.

#### MISSING_ROUTE_FUNCTION

**Cause:** `conditional()` was called without a `route` function.

**Fix:** Pass a `route` function that picks the next step at run time.

#### MISSING_BODY_STEP

**Cause:** `schedule()` was called without a body `step`.

**Fix:** Pass the step to run on each scheduled iteration.

#### INVALID_INTERVAL_MS

**Cause:** `schedule()` got an `interval` that is negative, `NaN`, or infinite.

**Fix:** Pass a non-negative number of milliseconds.

#### INVALID_JITTER

**Cause:** `schedule()` got a `jitter` that is negative, `NaN`, or infinite.

**Fix:** Pass a non-negative number of milliseconds, or omit `jitter`.

### Channels

#### INVALID_CHANNEL_TIMEOUT

**Cause:** A channel `send()` or `recv()` got a negative or `NaN` timeout. The call rejects with this error instead of waiting.

**Fix:** Pass a positive timeout in milliseconds, or `0` to wait with no timeout.

### Decide and routeSwitch

#### INVALID_DECIDE_QUESTIONS

**Cause:** `decide()` got an invalid question map: no questions, a boolean question with neither `instructions` nor `criteria`, a choice question with fewer than 1 or more than 255 values or duplicates, or a score question with fewer than 2 or more than 10 levels or duplicates.

**Fix:** Correct the question named in the error message.

#### INVALID_UNTIL_DECIDER

**Cause:** A decide step used as a loop's `until` (directly, or inside `any`/`all`) does not ask exactly one question, or its question is not boolean. Raised where the loop or combinator is built. Also raised if a decider predicate is called outside a loop.

**Fix:** Give the decider one boolean question whose yes means stop, e.g. `questions: { done: { type: 'boolean', instructions: 'Is the task finished?' } }`.

#### INVALID_DECIDE_SAMPLES

**Cause:** `decide()` got a `samples` value that is not a positive integer.

**Fix:** Omit `samples`, or pass a whole number of runs to average, for example `samples: 3`.

#### UNKNOWN_ROUTE_QUESTION

**Cause:** `routeSwitch()` routes `on` a question its decide step does not ask.

**Fix:** Set `on` to one of the decide step's question ids.

#### INCOMPLETE_ROUTE_CASES

**Cause:** `routeSwitch()` has no case for one or more outcomes of the question it routes on.

**Fix:** Give a case for every outcome named in the error message.

#### INVALID_MIN_CONFIDENCE

**Cause:** `routeSwitch()` got a `minConfidence` outside `[0, 1]`.

**Fix:** Pass a confidence between 0 and 1, for example `minConfidence: 0.6`.

#### MISSING_UNCERTAIN_STEP

**Cause:** `routeSwitch()` was called without an `uncertain` step.

**Fix:** Pass `uncertain`: the step to run when the model refuses or is not confident enough.

### Context Layers

#### INVALID_HISTORY_MAX_ITEMS

**Cause:** `history()` got a `maxItems` that is not an integer in the allowed range.

**Fix:** Pass a sensible cap such as `{ maxItems: 40 }`, or leave the layer out to keep history uncapped.

#### INVALID_BUDGET_INPUT

**Cause:** `allocateBudgets()` got `NaN` for a budget input (a layer budget, the total budget, or a reserve).

**Fix:** Pass a real number. `Infinity` is allowed and means uncapped.

### JSON Workflows

#### WORKFLOW_VALIDATION_FAILED

**Cause:** A workflow document does not match `WorkflowDocumentSchema`, one of its [expressions](/docs/framework/expressions) does not parse as JSONata, or `dynamicWorkflow()`'s planner failed to produce a valid document within its revision budget.

**Fix:** Correct the document against the [published JSON Schema](/docs/framework/json-runtime), and fix any expression syntax the message names (it gives the JSONata error code and position). For `dynamicWorkflow`, give the planner clearer instructions or a more capable model, or raise `maxRevisions`.

#### INVALID_WORKFLOW_SOURCE

**Cause:** `workflow()` got both or neither of `document` and `ref`.

**Fix:** Pass exactly one: `document: { version: 1, root: ... }` for an inline workflow, or `ref: '<name>'` with a `workflows` registry.

#### UNKNOWN_WORKFLOW_REFERENCE

**Cause:** A `workflow()` step's `ref`, or a `subflow` node, names a workflow that is not registered.

**Fix:** Register the workflow under that name in the `workflows` option (or `HydrationContext.workflows`).

#### WORKFLOW_RECURSION_LIMIT

**Cause:** Named sub-workflows recursed deeper than `maxRecursionDepth` (default `100`) on one execution path. Raised at execution time, when the ref one level too deep would resolve.

**Fix:** Give the recursion a base case, such as a `conditional` that stops calling the subflow, or raise `maxRecursionDepth` (`Infinity` removes the limit).

#### INVALID_MAX_RECURSION_DEPTH

**Cause:** `maxRecursionDepth` is not a positive integer or `Infinity`. Raised when a named ref first resolves.

**Fix:** Pass a positive integer such as `100`, or `Infinity`.

#### EXPRESSION_FAILED

**Cause:** An [expression](/docs/framework/expressions) failed at execution time: JSONata raised an error (such as arithmetic on a string), a `compute` expression gave no value or gave a function, or a test gave something other than a boolean. The message names the node and quotes JSONata's error code.

**Fix:** Fix the expression or the input it reads. A path that matches nothing gives no value, so check field names against the node's input.

#### EXPRESSION_LIMIT_EXCEEDED

**Cause:** An [expression](/docs/framework/expressions) ran past one of its limits: its step budget, its time budget, its nesting depth, or the size of a sequence it built.

**Fix:** Bound the recursion or data size in the expression, or raise the limits through `expressionLimits` on `parseAndRunWorkflow`, `dynamicWorkflow`, `workflow()`, or `HydrationContext`.

#### INVALID_EXPRESSION_LIMITS

**Cause:** An `expressionLimits` value is not a positive integer or `Infinity`.

**Fix:** Pass a positive integer for each limit you set, `Infinity` to lift one, or leave it unset to keep its default.

#### UNKNOWN_NODE_KIND

**Cause:** A workflow node has a `kind` the hydrator does not know.

**Fix:** Use one of the node kinds listed in the error's hint.

#### UNKNOWN_UNTIL_PREDICATE

**Cause:** A workflow loop's `until` predicate has an unknown `kind`.

**Fix:** Use one of `maxSteps`, `maxCost`, `maxDuration`, `noToolCalls`, `never`, `outputContains`, `outputEquals`, `converged`, `expr`, `any`, `all`, or `decide`.

#### UNKNOWN_TOOL_REFERENCE

**Cause:** A workflow node names a tool that is not in `HydrationContext.tools`.

**Fix:** Register the tool under that name in `HydrationContext.tools` before hydrating. The hint lists the tools that are registered.

#### UNKNOWN_LAYER_REFERENCE

**Cause:** A workflow node names a context layer that is not in `HydrationContext.layers`.

**Fix:** Register the layer under that name in `HydrationContext.layers`.

#### UNKNOWN_UI_LIBRARY_REFERENCE

**Cause:** A workflow node's output names a UI library that is not in `HydrationContext.uiLibraries`.

**Fix:** Register an output codec under that name, for example `uiLibraries: new Map([['my-lib', openUi(myLibrary)]])` with `openUi` from `@noetic-tools/openui`.

#### INVALID_OUTPUT_SCHEMA

**Cause:** A `callModel` or `acp-agent` workflow node's `output.schema` is not a JSON Schema that loads, for example a `$ref` that points nowhere.

**Fix:** Give a JSON Schema that `z.fromJSONSchema` loads, such as `{ "type": "object", "properties": { … } }`. See [Structured output](/docs/framework/json-runtime#structured-output).

#### UNKNOWN_PARAM_REFERENCE

**Cause:** A workflow node reads an option from a harness param (`fromParams`, or a `param` until predicate) that the harness does not have. It is raised before anything runs: by `parseAndRunWorkflow` and `dynamicWorkflow` when they check the document, and by the harness at the start of a run or turn of a hydrated document.

**Fix:** Pass the param to the harness, `new AgentHarness({ params: { pickModel: (ctx) => … } })`, or correct the name in the document. See [Options from params](/docs/framework/json-runtime#options-from-params).

#### PARAM_NOT_A_FUNCTION

**Cause:** A node names a harness param where only a function will do (`emitItems`, its `onStart` and `onDone` hooks, `onPermissionRequest`, a `param` until predicate) and the param holds another value.

**Fix:** Set the param to a function with the arguments the option's TypeScript form takes.

#### PARAM_NOT_ALLOWED

**Cause:** A document run by `parseAndRunWorkflow` or `dynamicWorkflow` reads a harness param the host did not grant. It is also raised, whatever the host granted, when such a document reads from a param an option that decides what a node may reach: `tools` on `callModel`; `tools`, `cwd`, `mode`, `model` or `onPermissionRequest` on `acp-agent`; `connection` on `call` or `wait`; `subject` on `verify`. The connection and ACP grants are checked against the document and cannot see a value a function gives later.

**Fix:** Name the param in the `params` option, `params: ['pickModel']`, or take it out of the document. A document may read no params unless the host names them. For the options listed, write the value on the node, or run a document you wrote with `hydrateWorkflow`.

#### PARAM_MUST_BE_SYNC

**Cause:** A node read an option whose TypeScript function is synchronous (loop `prepareNext` and `onError`, `routeSwitch` `on`, an `emit` filter, `replayKey`) from a param whose function gave a promise. For `replayKey` the error is logged, not thrown: like a `replayKey` that throws, the node runs without replay or recording.

**Fix:** Make the function return its value directly, not a promise.

#### INVALID_UNTIL_VERDICT

**Cause:** A loop's `{ "kind": "param" }` until predicate asked its function and got something other than a verdict.

**Fix:** Return `{ stop: true }` or `{ stop: false }`, with an optional `reason`.

#### UNKNOWN_ROUTE_TARGET

**Cause:** A `conditional` node routed by `fromParams.route` got an id from its function that none of its targets has.

**Fix:** Return the `id` of one of the node's route targets or its default, or nothing to take the default.

#### UNKNOWN_ACP_AGENT_REFERENCE

**Cause:** An `acp-agent` node names an agent that is not in `HydrationContext.acpAgents`.

**Fix:** Pass agent adapters via `HydrationContext.acpAgents`, for example `createAcpAgentRegistry(claudeCode())` from `@noetic-tools/acp`.

#### UNKNOWN_SUBPROCESS_REFERENCE

**Cause:** A `runCode` node names a subprocess adapter that neither `HydrationContext.resolveSubprocess` nor the harness's `environment.subprocess` has, or a `spawn` node, or a `runCode` node whose `execute` is a function, names one `resolveSubprocess` does not know (those two do not look among the harness's). The message lists the harness's names, unless the document is one `parseAndRunWorkflow` or `dynamicWorkflow` ran: its author is not told them.

**Fix:** Name one of the harness's adapters, map the name in `resolveSubprocess(ref)`, or omit `subprocess` to use the harness default.

#### INVALID_FORK_INPUT

**Cause:** A dynamic `inParallel` node (one with `each`) got input that is not JSON, or JSON that does not hold an array (at the `over` key, when set).

**Fix:** Feed the node a JSON array, or a JSON object with an array at the `over` key.

#### INVALID_REPLAY_KEY_INPUT

**Cause:** A node with `"replayKey": { "from": [...] }` got input that is not a JSON object, so the named properties cannot be read. You see it as a warning, not a thrown error: the node runs without replay or recording.

**Fix:** Feed the node a JSON object holding the `from` properties, or use `"replayKey": true` to key on the whole input.

#### INVALID_CUSTOM_ITEM_TYPE

**Cause:** A [custom item](/docs/framework/custom-items) was declared with a `type` that has no `prefix:` part.

**Fix:** Name it `prefix:name` after the Open Responses convention for extension items, e.g. `myapp:progress`.

#### INVALID_CUSTOM_ITEM_SHAPE

**Cause:** A custom item's JSON Schema does not load, or its `output` does not describe an object or a union of objects, or one of those objects declares `id` or `type`.

**Fix:** Give an object schema for `output`, or a union of object schemas (a discriminated union, a `z.union`, or a top-level JSON Schema `oneOf`/`anyOf` whose options are objects), and leave out `id` and `type`: the runtime adds both to every final item. Union options must be plain object schemas: an object with both `properties` and `oneOf`, options wrapped in `z.lazy`, and `.optional()`/`.pipe()` around the union are refused.

#### CUSTOM_ITEM_MISMATCH

**Cause:** `workflow({ customItems })` and its document declare one item name with different `type`s.

**Fix:** Give both declarations the same `type`, or rename one of them.

#### UNKNOWN_CUSTOM_ITEM

**Cause:** A step's `emitItems.item` names a custom item that is not in its scope: not on the step and, for a JSON node, not at its document's root.

**Fix:** Declare the item on the step (`customItems`) or at the workflow root.

#### CUSTOM_ITEM_HAS_NO_EVENTS

**Cause:** A hook or a generator `runCode` yielded an event, but the step's `emitItems` names no item, or names one declared without an `event` schema.

**Fix:** Name an item with an `event` schema in `emitItems: { item }`, or return the value instead of yielding it.

#### CUSTOM_ITEM_ALREADY_FINAL

**Cause:** One step dispatch gave a custom item a second final item, for example both `onStart` and `onDone` returned one.

**Fix:** Return the final fields from one hook only.

#### INVALID_CUSTOM_ITEM

**Cause:** An event or a final item does not match the schema its custom item declares. The message names the item `type`, the part (`event` or `output`), and the schema's issues.

**Fix:** Make the value match the declared `event` or `output` schema.

### ACP Agents

#### MISSING_ACP_AGENT

**Cause:** `step.acpAgent()` or `acpAgentTool()` has no agent adapter, or its lazy `agent` resolved to nothing at run time.

**Fix:** Pass an agent factory result, for example `agent: claudeCode()` from `@noetic-tools/acp`.

#### MISSING_PROMPT

**Cause:** `step.acpAgent()` was built with neither `prompt` nor `content`, or its prompt resolved to an empty string at run time.

**Fix:** Pass a non-empty `prompt` for plain text, `content` for image, audio, or resource blocks, or give the step a string input.

#### ACP_REUSE_WITHOUT_KEEPALIVE

**Cause:** A step sets `session.reuse` but leaves `keepAlive` at `'step'`, so the connection closes before another step can share it.

**Fix:** Add `keepAlive: 'run'` to share the connection for the rest of the run, or `keepAlive: 'harness'` to keep it past the run and close it yourself with `harness.close()`.

#### ACP_SESSION_AGENT_CONFLICT

**Cause:** A step reuses a session key that another step opened with a different agent.

**Fix:** Give every step that shares a `session.reuse` key the same agent, or use separate keys.

#### ACP_SESSION_CAPABILITY_CONFLICT

**Cause:** A step reuses a session but asks for different `clientCapabilities` than the connection was opened with. ACP negotiates capabilities once per connection.

**Fix:** Give every step that shares a `session.reuse` key the same `clientCapabilities`, or use a separate session.

#### ACP_SESSION_SETTING_CONFLICT

**Cause:** A step reuses a session but asks for a different `cwd`, different `instructions` or a differently set-up agent than the session was created with, or serves a tool the session's tool list lacks (the error names it). A resumed step that reattaches to a session opened with other instructions or agent settings fails the same way.

**Fix:** Give every step that shares a `session.reuse` key the same `cwd`, `instructions`, agent and `tools`, or use a separate session. A resumed step must resolve the same instructions and settings as the run that started it.

#### ACP_SESSION_ADAPTER_CONFLICT

**Cause:** A resumed step would reattach to an agent that outlived its host, but the step now resolves to another subprocess adapter than the one that started the agent: its `subprocess` name, its agent's, or the harness's default changed, or the entry was renamed. The agent may still be working where it was started, so the step attaches nowhere and fails. The check compares names: a host that keeps a name and puts another adapter behind it is not caught.

**Fix:** Resume with the step, its agent and `environment.subprocess` resolving to the adapter name the message gives, as in the run that started the agent.

#### AGENT_CAPABILITY_MISSING

**Cause:** A step asks an agent for something it did not advertise: `instructions` to an agent with no system prompt support and no adapter fallback, a `mode` or `model` it does not offer, or prompt content (images, audio, embedded resources) it does not accept. The message names the capability.

**Fix:** Leave that setting off the step, or use an agent that supports it.

#### ACP_TRANSPORT_CANNOT_REACH

**Cause:** `step.acpAgent()` gives `tools` to an agent attached through a custom `transport`. Noetic did not start that agent, and the transport has no `reach()` to carry the tool bridge to wherever it runs. With `tools` left out, such an agent simply gets none.

**Fix:** Give the agent a command and a subprocess adapter instead — `createLocalSubprocessAdapter()` from `@noetic-tools/platform-node` for this machine, or `createWebSocketSubprocessAdapter()` / `createCommandSubprocessAdapter()` from the same package for a remote runner (`noetic-acp serve`) — or leave `tools` off the step.

#### ACP_TRANSPORT_CANNOT_LAUNCH

**Cause:** As `ACP_TRANSPORT_CANNOT_REACH`, for an agent whose wiring has launch settings (Claude Code, Codex, opencode, pi): attached to an agent someone else started, those settings cannot be applied, so its tools would not match `callModel`.

**Fix:** Give the preset a `subprocess` adapter instead of a `transport`; its link's `launch()` starts the agent with those settings.

#### ACP_AGENT_CANNOT_TAKE_TOOLS

**Cause:** `step.acpAgent()` gives `tools` to `gemini()` without `trustWorkspace: true`. Gemini CLI starts no MCP server, the tool bridge included, in a folder it does not trust, so the agent would run with none of the tools `callModel` would offer.

**Fix:** Pass `gemini({ trustWorkspace: true })` to trust the session's folder for the agent process. Trusting it also loads the folder's own `.gemini/settings.json`, `GEMINI.md` and `.env`, so do this only for a repository you wrote; otherwise leave `tools` off the step.

#### ACP_SERVER_TOOL

**Cause:** `step.acpAgent()` was given a server tool such as `openrouter:web_search`. Only a model provider can run server tools.

**Fix:** Pass only client tools built with `tool()`.

#### ACP_TOOL_NAME_COLLISION

**Cause:** Two of a step's tools reduce to the same wire name (names keep only letters, digits, `_`, and `-`), so the agent could not tell them apart.

**Fix:** Rename one of the tools.

#### ACP_SERVE_KIND_RULES_WITHOUT_TOOLS

**Cause:** `serveAcp()` got a kind-based permission rule (such as `{ kind: 'execute' }`) but no `tools` to look kinds up from.

**Fix:** Pass the harness's tools in the serve options: `serveAcp(harness, { tools, permissions })`.


### Connections

#### CONNECTION_UNKNOWN

**Cause:** A handle, workflow node, trigger or allowlist names a connection the harness does not have, or a `connectionTools('<name>')` pick (or a JSON `{ "connection" }` pick) names one neither the harness nor the turn attaches, found when the turn's tool set is built.

**Fix:** Add the connection under that name in `new AgentHarness({ connections })`, or correct the name. The hint lists the connections the harness has.

#### CONNECTION_UNSATISFIED

**Cause:** A connection does not offer what is required of it. The error's `missing` field says which: a profile or extension version, an operation, an event, or a sense a `verify` step needs.

**Fix:** Point the handle or manifest entry at a connection whose server offers what is missing, or relax the requirement (a wider version range, fewer operations).

#### CONNECTION_NOT_ALLOWED

**Cause:** A JSON workflow asks for more than its `connections` allowlist grants, or sets a setup field the profile reserves to the host (such as the command or path of an app). Or an `acp-agent` node asks for more than the `acp` allowlist grants its agent (`permissions`, `mode`, `model`, `subprocess`, `fs`, `shell`, `cwd`, `clientCapabilities`, `session`), or a `runCode` node names a harness subprocess adapter the `runCode` grant does not list, or the document names an MCP server, header or environment value the `mcp` allowlist does not grant, or names one header or variable twice.

**Fix:** Widen the allowlist passed to `parseAndRunWorkflow` or `dynamicWorkflow`, or move the host-only field into the pool's own `setup` in the harness configuration. For an MCP server URL, write it as the message shows.

#### CONNECTION_INVALID

**Cause:** A connection manifest entry, handle or provider configuration is malformed: for example a bad version range, a `fresh` handle without a pool, a `secret()` or an MCP server `$secret` used with no `environment.secrets` resolver, an `mcp` allowlist URL pattern with `*` in the host other than a leading `*.` followed by at least two labels, a listed entry with no name, a record key that disagrees with `mcp({ name })`, a turn or step entry that sets `pool`, a function-form `tools` that returns a connection the turn never attached, an `mcp()` config that is not ACP's `McpServer` shape (a command line string, `protocol`, headers or environment as a record), a header or environment variable given twice, `auth` together with an `Authorization` header, a `connectionTools()` name that is not a connection name, or a document `{ "mcp" }` connection whose key disagrees with its name or that sets `from`, `fresh` or `setup`.

**Fix:** Correct the entry the message names. The hint says which field is wrong.

#### CONNECTION_TOOL_COLLISION

**Cause:** Two connection operations would reach the model under the same tool name.

**Fix:** Rename one of the connections, or set `expose: 'call'` or `'none'` on one of them.

#### CONNECTION_NAME_TAKEN

**Cause:** An entry names a connection that its scope or an outer one already attaches with a different provider or options. The scopes are the harness, then the turn (`execute(input, { connections })`), then a step's `tools`. Two entries in one list or record with the same name and different providers fail the same way. So do two `acpAgent` steps of one turn that list the same entry under different `subprocess` names: the entry is one connection, started in one place.

**Fix:** Pass the same entry object the outer scope uses, or give this one another name. Give steps that share an entry the same `subprocess`.

### Verification

#### VERIFY_NOT_CONFIGURED

**Cause:** A `step.verify` (or a `verify` workflow node) ran, but the harness has no verifier.

**Fix:** Register one: `new AgentHarness({ verification: verifier() })`, with `verifier` from `@noetic-tools/verify`.

#### VERIFY_INVALID

**Cause:** A verify step is malformed: its `act` contains nothing that acts, a matcher cannot be parsed by its sense's grammar, or a witness is asked to run an operation with effects.

**Fix:** Give `act` at least one call with effects on the subject, fix the matcher text the message quotes, and let witnesses only run operations without effects.
