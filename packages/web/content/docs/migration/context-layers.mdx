# Context Layer Naming Migration

This release makes the context-layer vocabulary consistent across builders,
layer IDs, storage keys, workflow documents, and tool names. It is a
**breaking change**: Noetic does not provide deprecated aliases, accept legacy
configuration keys, or ship `@noetic-tools/memory`.

Import context APIs from `@noetic-tools/context` or the equivalent re-exports
from `@noetic-tools/core`.

## Package and contract changes

```diff
- import { workingMemory } from '@noetic-tools/memory';
+ import { scratchpad } from '@noetic-tools/context';
```

`@noetic-tools/memory` has been removed. The layer contract uses
`ContextLayer`, and layer data is exposed through `ctx.context` and
`toolCtx.context`.

## Builder migration

| Before | Final API |
|---|---|
| `workingMemoryContext()` | `scratchpad()` |
| `observationalContext()` | `observations()` |
| `temporalContext()` | `temporal()` |
| `planContext()` | `plan()` |
| `toolContextLayer()` | `toolCalls()` |
| `staticContent()` | `instructions()` |
| `fileReference()` | `filesystem()` |
| `historyWindow()` | `history()` |
| `durableTaskState()` | `taskState()` |
| `layerFn()` | `layerFunction()` |

`steering()` is unchanged. Episodic and semantic recall remain documentation
recipes rather than exported built-in layers.

## Harness and step migration

Use `contextLayers` for default layers and the final AgentHarness configuration
shape:

```ts
import { AgentHarness, callModel, scratchpad } from '@noetic-tools/core';
import type { StorageAdapter } from '@noetic-tools/core';

// Your platform's storage adapter, e.g. `createFileStorage()` from
// `@noetic-tools/platform-node`.
declare const storage: StorageAdapter;

const harness = new AgentHarness({
  name: 'assistant',
  agentGraph: callModel({
    id: 'respond',
    model: 'openai/gpt-4o',
  }),
  params: {},
  contextLayers: [scratchpad()],
  environment: {
    storage: {
      adapter: storage,
    },
  },
});
```

The former `memory:` configuration key, `ctx.memory`, `toolCtx.memory`,
`initialStep`, flat environment adapters, and `llm` harness option have been
removed. See [AgentHarness](/docs/framework/runtime) for the full final
configuration surface.

## Persisted state and checkpoints

Built-in layer IDs changed with their builders:

| Final builder | Old layer ID | Final layer ID |
|---|---|---|
| `scratchpad()` | `working-context` | `scratchpad` |
| `instructions()` | `static-content` | `instructions` |
| `observations()` | `observational-context` | `observations` |
| `filesystem()` | `file-reference` | `filesystem` |
| `history()` | `history-window` | `history` |
| `taskState()` | `durable-task-state` | `task-state` |

Layer IDs namespace storage (`layers/{layerId}/…`), checkpoint state, and
model-visible layer tools. `CheckpointSchemaVersion` is now 2; version-1
snapshots are rejected with `CHECKPOINT_SCHEMA_MISMATCH` instead of restoring
with silently missing layer state. Clear the old checkpoint and start a fresh
execution—there is no automatic migration path.

JSON workflow documents that name built-in layers must use the final IDs.
